## 1. 現状報告

### 1-1. 現時点で動作する機能

新システムでは下記がブラウザから操作できる状態です（開発環境）。

| 機能 | 内容 |
|------|------|
| 現場・得意先・商品マスタ | 一覧・新規登録・編集・削除 |
| 現場×商品（補助） | 現場ごとによく使う商品を登録し、依頼画面で**上位表示**（並び替え補助） |
| 倉庫在庫の一覧 | 商品ごとの現在庫数を一覧表示 |
| 在庫の手動メンテ（暫定） | 数量を直接編集する管理者向け画面 |
| 入庫・出庫の登録 | 「入庫／出庫」「商品」「数量」を指定して在庫に反映。履歴も自動保存 |
| 在庫履歴（台帳）の閲覧 | 過去の入出庫履歴を一覧で確認 |
| 出庫依頼フロー | 依頼登録 → 受付 → 出庫確定（在庫が減る）／途中キャンセル |
| 在庫不足の検知 | 出庫確定時に在庫が足りなければ自動的に止まり、受付済みのまま戻る |
| 操作履歴（最小監査ログ） | 出庫依頼の **登録・受付・キャンセル・出庫確定** を後から SQL で追跡可能 |

### 1-2. 出庫依頼のステータスと業務上の意味

| ステータス | 意味 | 在庫の動き |
|------------|------|------------|
| 依頼中（requested） | 業者がオーダーを出した状態 | 動かない |
| 受付済み（accepted） | 本社／センターが受け付けた状態 | 動かない |
| 出庫済み（shipped） | 実際に出庫した状態 | **このタイミングで減る** |
| キャンセル（cancelled） | 依頼中／受付済みの時点で取消 | 動かない |

→ 「**実際に出庫したタイミングでのみ在庫が減る**」がシステム上のルールです（業務認識と一致）。

### 1-3. 整合性で保証していること

- 出庫の結果、**在庫がマイナスにならない**
- 受付・出庫確定の二重実行が発生しない
- 出庫済みの依頼を再度出庫することはできない
- 在庫が足りない依頼は、出庫ボタンを押しても**システム側で自動的に止まる**（受付済みのまま、在庫は減らない）

### 1-4. 業務運用上の確定事項（5/25 ヒアリング反映）

| 項目 | 確定内容 |
|------|----------|
| 業者向け在庫表示 | **倉庫在庫（センター残）寄り**で見せる方針 |
| 在庫不足時の業者対応 | 当面は**電話・LINE 等の既存運用を継続**（システムでブロックしない） |
| 現完滅失の登録 | サンプル建設様側で**手動登録**。固定タイミングなし（工事完了確認後） |
| リース別現場移動 | **リース会社へ連絡**する運用 |
| 現完滅失の改善・不足時注文不可 | **将来案**として認識（MVP には入れない） |

## 2. UAT で確認していただきたい項目

### 2-1. シナリオ一覧（MVP 範囲）

| ID | シナリオ | 期待結果 | OK |
|----|----------|----------|:--:|
| **U-A1** | マスタ登録：現場・得意先・商品を 1 件ずつ追加 | 一覧に表示される。編集・削除ができる | |
| **U-A2** | 現場×商品（補助）の登録 | 対象現場の依頼画面で、登録した商品が**上位に並ぶ**。未登録品も選べる | |
| **U-B1** | 在庫の手動登録：商品 1 件を center に数量 10 で登録 | 在庫一覧に「10」と表示される | |
| **U-B2** | 入庫：上記商品を 5 入庫 | 在庫一覧が「15」に。履歴に IN 5 が残る | |
| **U-B3** | 出庫（直接）：上記商品を 3 出庫 | 在庫が「12」に。履歴に OUT 3 が残る | |
| **U-C1** | 出庫依頼：在庫十分な商品で依頼→受付→出庫確定 | 在庫が依頼数だけ減る。履歴・依頼ステータスが連動 | |
| **U-C2** | 出庫依頼：依頼中の段階でキャンセル | 在庫は変わらない。ステータスが「キャンセル」になる | |
| **U-C3** | 出庫依頼：受付済みの段階でキャンセル | 在庫は変わらない。ステータスが「キャンセル」になる | |
| **U-C4** | 在庫不足：在庫 0／不足の商品で出庫確定を試す | システムが**自動的に止め**、依頼は「受付済み」のまま。在庫は減らない | |
| **U-C5** | 出庫済みの依頼を再度出庫・キャンセル | どちらもできないことを確認 | |
| **U-D1** | 同じ商品に対し、別タブから 2 件同時に出庫確定 | どちらかは成功・どちらかは在庫不足で止まる（**マイナス在庫が発生しない**） | |
| **U-D2** | 出庫依頼の登録〜出庫確定までを 1 件追跡 | 一覧・詳細・履歴のいずれでも整合した状態で見える | |

### 2-2. UAT 不要・MVP 対象外（参考）

下記は今回の UAT では対象外です（`docs/05` §5 / 本書 §3-2 と整合）。

- システム内通知（誰に何が通知されるか）
- LINE 通知
- 残少アラート
- 認証・業者専用画面・権限分離
- 貸出在庫・リース・現完滅失・振り分け表
- Excel / 伝票出力
- 希望納期・納期不可ワークフロー

### 2-3. 合格基準

- 上記 **U-A〜U-D の全シナリオで「期待結果」と一致**すること。
- 一致しない場合は、**業務的に致命的か否か**（出荷・在庫数字が狂うか）で P0／P1 を仕分けます。
- **P0 欠陥がゼロ**になった時点で UAT 合格扱いとします。
