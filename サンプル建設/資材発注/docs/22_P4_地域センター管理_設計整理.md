## 1. 背景と目的

現行システムはサンプル市Aセンター1拠点のみを前提に作られている（[docs/20](./20_P1-E_決定事項.md) D-20260801-15）。今回、関東（サンプル市B）・九州の運用が実際にはあり、それぞれの地域担当が「自分の地域の在庫だけ」を見られるアカウントが欲しいという要望が出た。あわせて、サンプル市A→サンプル市Bのようなセンター間の資材移動を、システム上で「センターへの出庫」として記録したいという要望も出た。

## 2. 決定事項（ヒアリング + ユーザー回答, 2026-08-19）

|---|------|----------|
| 1 | 拠点の範囲 | **関西（サンプル市A）／関東（サンプル市B）／九州の3センター**。今後の拡張は現時点で想定しない |
| 2 | 現場の地域区分 | 現場マスタに地域（センター）を持たせる。**既定値は関西**。設定・変更できるのは**事務（admin）のみ**。既存のGAS連携（現場データの自動流し込み）には触れない（GAS側の変更は不要な形で実現する） |

## 3. 現行コードへの影響（調査結果）

現行DBは「センターは1つ」という前提が構造レベルで組み込まれている。

- `stock_items` 等の `storage_kind` は `'center' / 'site'` の2値のみで、**どのセンターかを区別する列がない**（`資材管理実装/web/supabase/migrations/020_p1b1_stock_items_site.sql`）
- `sites` テーブルに地域・拠点を表す列は**存在しない**（`003_sites.sql`）
- `app_users.role='center'` は拠点に紐づく列を持たず、**centerロールは常に「唯一のセンター」を指す前提**（`026_p3_0a_role_foundation.sql`）
- 在庫移動・出庫・返却・分析系のRPC（`apply_stock_movement`, `ship_stock_request`, `return_from_site` 等）で `location='center'` という**文字列リテラルが30箇所以上**に直接埋め込まれている（`027_p3_0a_role_split.sql`, `033`, `046`, `051`, `075`, `080`, `084` 他）

→ 「地域＝センターを増やす」ことは列追加だけでは済まず、**上記の暗黙の「センターは1つ」という前提を明示的な拠点IDに置き換える**構造変更になる。既存のサンプル市Aセンター運用・既存アカウントの挙動を壊さないことを最優先に、段階的に置き換える設計とする。

## 4. 概念設計（ドラフト）

### 4-1. 拠点マスタ

```
centers（新設）
  id, code（例: kansai / kanto / kyushu）, name（関西（サンプル市A）/ 関東（サンプル市B）/ 九州）, created_at
```

初期データとして3行を投入。既存の `storage_kind='center'` の在庫データは**全て関西（サンプル市A）センターに帰属**として扱う（後方互換）。

### 4-2. 現場の地域区分

`sites.center_id`（`centers.id` 参照, NOT NULL, 既定値=関西センターのid）を追加。事務（admin）のみ更新可能。

### 4-3. アカウントの地域スコープ

`app_users.center_id`（`centers.id` 参照, center ロールのみ使用）を追加。

- 既存の center ロールアカウントは**関西センターに自動割当**（後方互換、挙動変更なし）
- 新規の九州・関東アカウントはそれぞれの `center_id` を持つ
- RLS/権限チェックを「role='center'」だけでなく「`center_id` が一致する拠点・現場のみ」に絞る形へ拡張

### 4-4. 地域在庫ビュー

既存の `material_stock_breakdown`（`035_p3_2_stock_breakdown_view.sql`）に `center_id` を持たせ、アカウントの `center_id` で絞り込んだ上で「センター在庫合計」「紐づく現場在庫合計」をそれぞれ・合算の両方で提示する画面を追加する。

### 4-5. センター間移動

```
center_transfers（新設・ヘッダー）
  id, from_center_id, to_center_id, transferred_by（app_users）, transferred_at, note

center_transfer_items（新設・明細）
  id, transfer_id, product_id, quantity
```

- 入力は centerロールのみ（自分の拠点が `from_center_id` になる移動のみ起票可）
- 登録と同時に在庫反映（移動元センターの `stock_items` を減算、移動先センターを加算）。事務承認による在庫反映ブロックは行わない（決定事項#5）
- 事務は一覧・履歴を閲覧できる（更新権限なし）

## 7. Phase 1 実装内容（2026-08-19）

**migration**: `資材管理実装/web/supabase/migrations/089_p4_center_regions.sql`（**Supabaseへは未適用**。作成のみ）

- `centers` マスタ新設（関西/関東/九州の3行固定。RLSは select のみ admin・center に許可、write policyなし＝フェイルクローズ）
- `sites.center_id` / `app_users.center_id` / `stock_items.center_id` を追加。既存データは全て関西（サンプル市A）へ後方互換割当て
- `apply_stock_movement` は insert 部分のみ更新（center_id を明示設定）。シグネチャ・権限チェック・既存30箇所以上の呼び出し側は無改修
- `center_stock_location()` / `current_center_id()` / `default_kansai_center_id()` ヘルパーを追加。関西は既存互換のため `location='center'` のまま（データ移行不要）、関東は `'center:kanto'`、九州は `'center:kyushu'`
- `configure_app_user_by_admin` に `p_center_id` を追加（未指定は関西へフォールバック）。`list_app_users` に `center_id`/`center_name` を追加
- center ロールの参照RLS（`069_center_read_only.sql` の `*_center_read` policy 群）を自地域スコープへ更新（sites / site_products / stock_items / orders / stock_requests / lease_stock_items）。`products_center_read` は地域に無関係のため無変更

**アプリ側**（`資材管理実装/web/src/`）:

- 事務向け：現場の編集画面（`/sites/new`, `/sites/[id]/edit`）に「地域センター」選択を追加（既定=関西）
- 事務向け：アカウント発行・編集画面（`/users/new`, `/users/[id]/edit`）に、role=center 選択時のみ「担当地域」選択を追加
- centerロールの `/stock`（センター在庫）画面：自地域のセンター在庫に加えて「紐づく現場在庫合計」「地域内合計（センター＋現場）」を表示（決定事項#4）。admin の挙動・関西centerアカウントの見える範囲は変更なし
- `npx tsc --noEmit` / `npx eslint` で確認済み（本体のビルド・DBへの適用は未実施）

## 8. Phase 2 実装内容（2026-08-19）

**migration**: `資材管理実装/web/supabase/migrations/090_p4_center_transfers.sql`（**Supabaseへは未適用**）

- `center_transfers`（ヘッダー：from/to センター・起票者・備考）／`center_transfer_items`（明細：商品・数量・移動前在庫数量・不足数量のスナップショット）を新設
- `create_center_transfer(p_to_center_id, p_items, p_note)` RPC：centerロールが自センターから他センターへ資材を移動。登録と同時に1トランザクションで即時反映（移動元マイナス・移動先プラス）。既存の `apply_stock_movement` は在庫不足をブロックする実装のため再利用せず、本RPC内で「警告のみで許可」ロジックを直接実装（`shortage_quantity` に不足数量を記録）
- RLS: 追記専用ログとして扱う（update/delete policyなし）。admin は全件参照、center は自センターが from/to のいずれかの行のみ参照。テーブルへの直接insertは許可せず、RPC経由のみ

**アプリ側**:

- 新画面 `/stock/transfers`：centerロールは移動登録フォーム（移動先センター選択＋商品・数量の複数行入力）＋履歴一覧、adminは履歴一覧のみ（閲覧専用）
- `access-rules.ts` に `/stock/transfers` を追加（admin/center許可、vendorは対象外）。**未登録だとcenterロールは既定拒否のため必須の対応**
- `CenterSectionNav` に「センター間移動」タブを追加

**admin向け `/stock` 画面の表示変更**（同日、ユーザー指摘により追加修正）:

- センター選択タブ（関西/関東/九州）はそのまま維持
- 新たに「センターのみの在庫」／「センター＋紐づく現場の在庫」の表示切替タブを追加
- 統計カードを「センターのみ合計」中心の表示に整理（センターのみ表示時は2枚、combined時は現場合計・地域内合計を含む4枚）
- 保管場所列は生の `location` 文字列ではなく、センター名／現場名を表示するよう改善

## 9. 未適用の migration（要確認）

`089_p4_center_regions.sql` と `090_p4_center_transfers.sql` は**作成のみでSupabaseに未適用**です。適用順序は 089 → 090。089は一度SQLエディタでの初回適用時に列参照順序の不具合を修正済み（`current_center_id()` を `app_users.center_id` 追加後に定義する形へ移動）。適用前に内容を確認してください。
