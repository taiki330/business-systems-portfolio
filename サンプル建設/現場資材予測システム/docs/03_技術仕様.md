# 技術仕様

作成日: 2026-09-15

## 1. 実行環境

- Python。ライブラリは `_common/runtime/` に配置済み（ezdxf, ezjww, pymupdf 等）。
  現場フォルダごとに個別のライブラリは持たない（共有）。
- 実行前に `PYTHONPATH` に `_common/runtime` を通す必要がある。

**配布用zipには `_common/runtime`（約240MB、ライブラリ本体）を含めていない。**
`_common/requirements.txt` を元に、以下のいずれかで環境を再構築すること。

```powershell
# 案1: そのままインストールし、通常のPYTHONPATH設定なしで使う
pip install -r .\_common\requirements.txt

# 案2: 元の環境と同じくローカルディレクトリに閉じ込める場合
pip install -r .\_common\requirements.txt --target .\_common\runtime
$env:PYTHONPATH = (Resolve-Path '.\_common\runtime')
```

```powershell
$env:PYTHONPATH = (Resolve-Path '.\_common\runtime')
python .\サンプル現場B\claude_output\scripts\analyze_site.py
python .\サンプル現場A\claude_output\scripts\analyze_seido1.py
```

各スクリプトは自分の場所からの相対位置（`Path(__file__).resolve().parents[N]`）で
現場フォルダ・`_common`フォルダを見つけている。**フォルダの「名前」には依存していない**ので、
現場フォルダをリネームしてもスクリプトは壊れない（2026-08-31 に実際に検証済み）。
ただし、現場フォルダが `現場資材予測システム/` 直下の1階層目にあることは前提にしている。

## 3. 数量抽出の基本ロジック（JWW共通）

### 3.1 シートの分割

1枚のJWWファイルには、平面図・立面図・断面図など複数の図面が横一列に並んでいる。
これを分けるために、**図枠ブロック（`Zuwaku_Nikken_JPN`）のx座標**を使う。
1シートに1個ずつ配置されているため、そのx座標をシートの境界とする。

### 3.2 重複計上の排除（レイヤベース）

同じ部材が平面図・立面図・断面図に重複して描かれる。**レイヤごとに「どのシート種別を正とするか」を
固定**することで、二重計上を防いでいる（`analyze_seido1.py` の `LAYER_RULE`）。

| レイヤ | 採用するシート種別 |
|---|---|
| `NRG2_NDSystemSide`（部材本体） | 立面 |
| `NRG2_NDSystemWallTie`（壁つなぎ） | 立面 |
| `NRG2_養生部材` | 立面 |
| `NRG2_ジャッキ` | 立面 |
| `NRG2_伸縮ブラケット` | 平面（立面には描かれないため） |
| `NRG2_Step`（階段） | 平面 |
| `NRG2_建枠正面`（単管等） | 不採用（断面にしか無く代表範囲が不明。確認事項） |
| `NRG2_NDSystemPlan`, `NRG2_Dim`, `NRG2_DrawingFrame` 等 | 不採用（部材ではない） |

### 3.3 品番の分類（正規表現）

品番から資材の大分類を判定する（`CATEGORY_PATTERNS`、先に一致したものを採用）:

```
ジャッキベース: A752$
支柱:          NHP
布板:          SKN または BKN
先行手すり:     NHX
つなぎ材:       NDT
壁つなぎ:       KS + 数字
鋼製足場板:     NB + 数字
階段まわり:     NHAL, NDKH, SG
手すり枠:       TWL
```

## 4. 列数判定ロジック（`row_detect.py`）— サンプル現場Aのみ対応

立面図では、足場の内側の列と外側の列が重なって1本にしか描かれない。
これを補正するために、**断面図に描かれたジャッキベースの間隔（610mmピッチ）を実測し、
実際の列数を判定する**。

処理の流れ:

1. 平面図上の断面記号（レイヤ `NRG2_CrossSectionMark`）から、A-A・B-B等の切断線を復元する
   （同じ記号の丸が2つあり、その2点を結んだ線が切断線）
2. 切断線の向きで、どの面（東西／南北）を切っているかを判定する
3. 該当する断面図のジャッキベースを、610mmピッチで連続する塊にまとめる。
   1つの塊の本数がその面の列数
4. 立面図の各シートに描かれている面の名前（「南立面図」等）から、
   そのシートに適用する列数を決定する

**この手法は `NRG2_CrossSectionMark` レイヤが存在する図面テンプレートでのみ動作する。**
サンプル現場BのJWWにはこのレイヤが存在せず、そのままでは使えない
（別の作図方式のため。ジャッキベース自体は存在するので、断面図のジャッキ間隔を
直接測る方式に作り替えれば対応できる可能性があるが未着手）。

判定した列数を、分類ごとに以下のルールで数量へ反映している（`ROW_RULE`）:

```
支柱・ジャッキベース・つなぎ材・先行手すり: 数量 × 列数
布板・壁つなぎ・鋼製足場板・階段まわり・手すり枠: 数量 × 1（列数を掛けない）
```

**この分類別ルールの妥当性は未確定な点が残っている。** `ROW_RULE_BASIS` という変数に
「10号棟の手拾い実績で校正（支柱 誤差1.2%）」という説明がコード内コメントとして
残っているが、これは統合作業の初期時点のものであり、**2026-09-15 に再実行した結果は
支柱誤差17.4%だった**（`02_現状サマリ.md` 3節）。コード内コメントの数値は信用せず、
実行結果を都度確認すること。

## 5. 資材名の対応表

品番から日本語名への対応は `analyze_seido1.py` の `MATERIAL_NAMES` 辞書にハードコードされている。
以下は**名称が未確定のまま数量には計上している**品番（NFG系）:

```
NFG18, NFG15, NFG12, NFG09, NFG06, NFG06TA
```

10号棟で374〜921本という無視できない数量がある。図面上の位置関係（布板の直下52mmに
必ず配置される、長さの体系が布板・先行手すりと同じ）から「幅木」の可能性が高いと
推測しているが、確証はない。`05_未解決事項と次のアクション.md` 参照。

## 6. ファイル判別ロジック

各スクリプトの `FILE_RULES` 辞書に、ファイル名と判別結果・根拠をハードコードしている。
**新しい現場を処理する際は、この辞書を都度手動で追加・調整する必要がある。**
ファイル名から自動で「これは足場計画図」「これは建築図」と判定する汎用ロジックには
なっていない（PDFの文字数・拡張子等からの簡易な自動判別は行っているが、
最終的な分類はハードコードされた辞書が優先される）。
