## 3. `/requests/new` での使い方（確定）

### 3-1. 画面の振る舞い

1. ユーザーが**現場**を選択する（既存どおり）。
2. 商品プルダウンは **全 `products` を表示**する（フォールバック保証）。
3. 選択した現場に紐づく `site_products` 登録品は**リスト上位**に並べる。
4. 未登録品は**リスト下位**に並べる（選択は可能）。
5. **登録品・未登録品のいずれも依頼作成は可能**（バリデーションでブロックしない）。

### 3-2. MVP で行わないこと

- 未登録品の選択禁止（厳格ホワイトリスト）
- 未登録品選択時の警告ダイアログ・確認モーダル
- 未登録品選択時の `note` 必須化
- 「登録商品 / その他」の別タブ・別ドロップダウン（P4）は MVP では採用しない（Q-2 = C のため）
- 完リース品・リース品を site_products で管理する前提

### 3-3. マスタ未整備時の運用

- `site_products` が空、または当該現場に 1 件も無い場合でも、**全商品から依頼作成できる**こと（現状と同じ挙動を維持）。
- 整備が進むほどプルダウン上部に現場向け商品が集まり、**誤発注の抑止効果が自然に上がる**（補助として機能）。

## 4. 完リース・特殊材との境界（確定）

| 区分 | site_products 対象 | 理由 |
|------|:--------------------:|------|
| 自社在庫品（center から出庫する通常品） | ✅ 対象 | `/requests` の shipped 化と整合 |
| 完リース品 | ❌ 対象外 | 自社在庫を持たない。`/requests` の center 出庫と矛盾（`docs/10` §2-3） |
| リース品（他社所有） | ❌ 対象外 | リース手配フロー未実装（`docs/10` §3-2） |
| 特殊材（運用が個別） | ❌ 対象外（MVP） | 例外運用が多く、厳格紐づけは危険 |

- 完リース・リースの依頼経路は **リース手配フロー実装フェーズ**で別途整理する（本 doc では決めない）。
- `products` テーブル上で自社在庫品と完リース品を**どう識別するか**は未確定（`docs/10` §5-2）。MVP 実装時は、識別方法が決まるまで site_products 登録対象の切り分けは**運用（マスタ登録ルール）**で補う。

## 5. 制限 vs 補助（確定）

| 段階 | 方針 |
|------|------|
| **MVP** | **補助**（並び替えのみ。未登録品も選択可） |
| **将来（未確定）** | マスタ整備完了・例外フロー確定後に、警告（ソフト制限）や厳格制限へ昇格するかは**別途ヒアリング** |

MVP では「業務を止めない」を最優先とする。

## 8. 既存実装との関係（事実）

| 項目 | 現状 |
|------|------|
| `site_products` | **実装済み**（`006_site_products.sql`、`/sites/[id]/products`） |
