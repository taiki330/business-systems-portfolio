# 引き継ぎ資料 索引

作成日: 2026-09-15
対象読者: 本プロジェクトを引き継ぐ担当者

## このプロジェクトは何か

足場計画図（JWW / DXF / PDF）から資材の予定数量を自動で読み取り、
社内の資材発注システム（`サンプル建設/資材発注/資材管理実装/web`）の「予定数量」機能に
取り込める形式で出力する仕組みを作っている。詳細は `01_要件定義書.md` を参照。

## 読む順番（推奨）

1. **`01_要件定義書.md`** — 何を目指しているか、対象システムとの関係
2. **`02_現状サマリ.md`** — 今どこまで動くか、現場ごとの状況
3. **`03_技術仕様.md`** — どういう仕組みで数えているか、ファイル構成
4. **`04_精度検証データ.md`** — 実測値との突き合わせ結果（数値の生データ）
5. **`05_未解決事項と次のアクション.md`** — 引き継ぎ時点で残っている課題、優先順位

## 最初に知っておくべき重要な事実（3点）

1. **精度の実績値に、過去の会話と食い違いがある。** `04_精度検証データ.md` の冒頭を必ず読むこと。
2. **検証できているのは実質1現場（サンプル現場A10号棟）だけ。** 他はまだ答え合わせをしていない。
3. **元の図面ファイルは一切変更していない。** すべてコピーではなく参照のみで処理している
   （`サンプル現場B/`, `サンプル現場A/` 直下のファイルは受領時のまま）。

## フォルダ構成の要点

```
現場資材予測システム/
  docs/                    ← このドキュメント群
  _common/runtime/         ← 両現場が共有するPythonライブラリ（ezdxf, ezjww, pymupdf等）
  サンプル現場B/          ← 現場1の元ファイル + claude_output/（処理結果）
  サンプル現場A/                 ← 現場2の元ファイル + claude_output/（処理結果）
  _要確認_混入書類/          ← どちらの現場にも属さない、混入していた書類
```

現場フォルダの命名は仮のもの。作業番号（例: `L00001901126`）をキーにする案を検討中だったが、
2026-08-31時点で保留のまま。`05_未解決事項と次のアクション.md` を参照。
