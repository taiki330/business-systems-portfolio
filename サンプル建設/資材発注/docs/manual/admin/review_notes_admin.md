# 事務（admin）マニュアル作成時の気づき・要確認事項

マニュアル執筆のためにコードとスクリーンショットを確認する中で気づいた、コードと画面の食い違い・表記揺れ・要確認事項を記録する。いずれも今回のマニュアル作成では修正していない（記録のみ）。

## 1. オーダー詳細画面に「出庫確定」ボタンが admin には無い（タスク前提との食い違い）

- 画面: オーダー詳細 (`/orders/[id]`)
- 内容: `src/app/orders/[id]/page.tsx` の出庫完了セクションは `{isCenter && (...)}` で囲まれており、`canCompleteShipment` も `isCenter && ...` で判定している。`src/app/orders/actions.ts` の `completeOrderShipment` も `requireCenter()` を呼んでおり、admin は呼び出せない。
- なぜ気になったか: 今回の執筆指示（および一般的な想定）では「事務がオーダー確認・数量変更・明細追加・出庫確定・印刷を行う」とされていたが、実装上は出庫確定はセンター（center）ロール専用で、事務（admin）の画面には出庫確定のボタン自体が表示されない。スクリーンショット `orders-detail.png` でも出庫完了セクションが表示されないことを確認した。マニュアルは実装に合わせて「出庫確定はセンターの操作」である旨を明記した。将来的に admin にも出庫確定を持たせる想定があるなら、要件と実装のどちらが正か確認が必要。

## 2. 現場マスタに「元請名」「伝票用現場番号」を表示する列が一覧にも編集画面にも無い

- 画面: 現場マスタ一覧 (`/sites`)、現場編集 (`/sites/[id]/edit`)
- 内容: `src/app/sites/page.tsx` は `prime_contractor_id, slip_site_number` を select しているが、テーブルの `<th>/<td>` には出力していない（データを取得しているのに表示していない）。さらに `src/components/sites/SiteForm.tsx` も `site.slip_site_number` をどこにも表示しておらず、元請の選択プルダウンだけが表示される。
- なぜ気になったか: 執筆指示では「一覧には出ない、編集画面を開けば確認できる」という想定だったが、実際には編集画面を開いても採番済みの伝票用現場番号そのものは表示されない（元請の選択状態しか見えない）。現状、事務が伝票用現場番号を確認できるのは、その現場のオーダーが1件以上作られたあとの資材発注書印刷画面のみ。現場を新規登録した直後で、まだオーダーが1件も無い場合、伝票用現場番号が何番になったかをUI上で確認する手段が無い。実装漏れの可能性が高く、確認・修正を検討したほうがよい。

## 3. 「予定数量超過の確認」「半端もんの確認」の一覧から admin がアクセスできない依頼詳細へのリンクがある

- 画面: 予定数量超過の確認 (`/plans/over`)、半端もんの確認 (`/plans/lot-size`)
- 内容: いずれの一覧も各行に `href={`/requests/${r.request_id}`}` の「依頼詳細」リンクがある。`src/lib/auth/access-rules.ts` では `/requests/[id]` 系は admin: forbidden。
- なぜ気になったか: 事務のアカウントでこのリンクを押すと `/forbidden` にリダイレクトされる想定で、事実上デッドリンクになっている。事務専用ページ（`plans_over`, `plans_lot_size` は admin のみ allow）にある唯一の詳細導線が、事務からは開けない画面を指しているのは画面設計としての矛盾。centerやvendor向けの導線を admin 画面に流用した可能性がある。

## 4. リース借用詳細の受入・出庫・返却操作コメントとロールガードの不一致（実害なし、コメントのみ）

- 画面/コード: `src/app/leases/batches/actions.ts` の `receiveLeaseBatchItem` / `shipLeaseStockToSite` / `returnLeaseStockFromSite` / `returnLeaseToCompany`
- 内容: ファイル先頭のコメントには「受入・出庫・返却は center のみ」と書かれているが、各関数の実装は `requireAdmin()` を呼んでおり、実際に操作できるのは admin のみ（`canShowLeaseStockActions` も admin のみ true を返す）。
- なぜ気になったか: コード内コメントと実装が食い違っている。動作は admin 側で正しく機能しており、マニュアルは実装（admin が受入・出庫・返却を行う）に合わせて記載したが、コメントの記述と将来のロール割り当て変更（center への委譲）を検討する際に混乱を招く可能性があるため記録する。

## 5. 商品マスタ・元請マスタなど「用語」の表記揺れ

- 「商品マスタ」（画面見出し）と「資材」（フォーム内のラベルや案内文、例:「資材名・コードの一部を入力」）が随所で混在している。ユーザー向け文言としては同じ対象を指しているが、画面によって「商品」「資材」の呼び方が統一されていない（例: `/products` の見出しは「商品マスタ」だが検索プレースホルダーは「資材名・コードの一部で検索」）。
- なぜ気になったか: マニュアルは画面の実際の文言をそのまま使う方針のため、この表記揺れをそのままマニュアルにも反映した（例えば商品マスタの節で「資材」という語も使っている）。UI側で用語を統一すると、利用者の混乱が減ると考えられる。

## 6. 元請マスタに削除ボタンが無い

- 画面: 元請マスタ (`/prime-contractors`)
- 内容: `src/app/prime-contractors/page.tsx` には行ごとの更新フォームのみで、削除アクションが存在しない（`src/app/prime-contractors/actions.ts` にも `deletePrimeContractor` に相当する関数が無い）。他のマスタ画面（商品・現場・業者・リース会社・仕入先）は一覧に「削除」ボタンがあるのに対し、元請マスタだけ「利用中」チェックを外す方式のみになっている。
- なぜ気になったか: 他のマスタ画面との操作性の一貫性が無い。意図的な設計（元請は履歴上消せない方が安全という判断）である可能性もあるが、念のため記録する。
