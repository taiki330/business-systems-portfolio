# 給与集計システム 要件定義書

作成日：2026年10月15日 ／ 版：0.2（実装準拠）

本書は現在のソースコードに実装されている動作を基準とする要件定義書である。資料とコードが異なる場合はコードを優先する。集計範囲・按分・警告・上書き等の実装済み動作を現行要件とし、追加機能や改善案は含めない。実装から判断できない運用情報は第9章に分離する。プログラムの変更は行っていない。

## 1. 目的・対象範囲

キングオブタイムで確定した給与・賞与CSVを取り込み、医院別の人件費と振込額を集計し、既存の給与売上入力シートおよび共有用Excelを作成する。毎月の転記作業を減らし、対象者の計上漏れと医院別集計の誤りを確認しやすくする。

給与・賞与の算定、勤怠計算、税・社会保険料の計算、銀行への振込、給与明細の発行は現行処理の対象外。ハノワの請求分を取り込む機能はない。資料上は出力Excelへの手入力で扱うが、手入力内容を共有用Excelへ再反映する機能は実装されていない。

## 2. 利用者・業務フロー

- 給与担当者：CSV取得・配置、従業員登録、集計実行、結果確認、共有用ファイルの送付、バックアップを行う。
- 医院側の受領者：共有用Excelの医院別金額と別枠の按分額を確認する。
- 保守担当者：既存マスタ・配分ルール・テンプレート・プログラムを管理する。

資料では毎月10日締め、28～29日振込を想定する。担当者が必要なCSVを「入力」に配置し、「実行.bat」を起動する。支給日・読込ファイル・警告・金額を確認してから、共有用Excelを通常のメール画面で添付・送信する。警告がある場合は内容を確認するまで共有しない。

| IO-04 | 従業員マスタ | `tool/従業員マスタ.csv`。社員番号・氏名・所属医院・区分・入力シート行・按分ルール・状態・備考を管理する |

## 5. 按分・端数処理（実装済み要件）

| 対象（社員番号） | 支給合計 | 差引支給合計 |
|---|---|---|
| 訪問・歯科A院兼務（019） | 給与＋賞与を合算し、訪問4/5・歯科A院1/5を別枠表示 | 給与・賞与それぞれについて訪問4/5・歯科A院1/5を医院別振込合計に含める |
| 事務（435） | 技工士2名と給与・賞与を合算し、4医院へ各1/4を別枠表示 | 所属医院（現状サンプル商事）へ計上する |
| 技工士（084・425） | 上記事務と合算して4医院へ各1/4を別枠表示 | 医院別振込額には計上しない |

4医院は、にしさんそう・歯科B院・歯科A院・サンプル商事。訪問は含まない。支給側の按分額は医院別の本表・合計には含めず、受領側で加算する方式。

按分はExcelのROUND(x,0)に合わせ、0.5を絶対値が大きい側に丸める。4等分では各医院の丸め後合計に端数差が生じ得るが、現状の支給突合は按分前の原資で比較する。CSV金額の読込は空欄・「-」を0とし、小数値にはPythonのroundを使用するため、按分とは丸め方式が異なる。

## 6. 警告・中止・整合性（現状）

| 条件 | 現行動作 |
|---|---|
| 通常給与3種類の不足 | 警告して処理継続。賞与CSVの不足は自動判定しない |
| 同一社員番号が同じ給与／賞与区分内で重複 | 警告して処理継続。ファイル名順で先に読み込んだ1件を採用し、後続は金額に加算しない |
| 未登録社員番号 | 中止する |
| 未知の所属医院 | 医院へ計上する対象者について中止する |
| CSVヘッダー・必要金額列なし | 中止する |
| 追加登録Excelの入力不備 | 中止する |
| 金額突合不一致 | 支給は医院別支給額＋按分前原資、振込は医院別振込額と対象者総額から技工士振込を除いた額を比較し、1円でも不一致なら中止する |
| 出力Excelが開かれている等で保存不可 | 中止し、閉じて再実行するよう案内する |
| 入力フォルダにCSVなし | 参考データが存在すれば参考データを処理する旨を表示して実行。参考データもなければ中止する |

注意：旧手順書の重複に関する「二重計上」の説明と実装は異なる。また、「中止時はファイルが1つも作られない」とは一律に保証できない。現状は履歴更新後にExcelを順次保存するため、保存途中の失敗で履歴のみ更新、または一部ファイルのみ出力となる場合がある。

## 7. 運用・非機能要件

- 現状：Windowsのローカルフォルダで利用する。実行batはexeがあればexeを優先し、なければPythonを使用する。Python実行ではopenpyxlが必要。出力の閲覧・原本数式の再計算にはExcelを想定する。
- 現状：全体インストーラーは既存の `C:\給与計算` があればそこを使用し、なければ `%LOCALAPPDATA%\給与計算` を既定にする。旧納品資料の設置先と異なる。
- 現状：集計の通常起動経路は出力フォルダを開いて終了し、メール送信や送信ブック更新を呼び出さない。手動でファイルを添付して共有できる。別起動の送信機能は下記のとおり実装されている。
- 現状：給与CSV・個人別出力・名簿・履歴・確認記録をローカルに保存する。アプリ内の認証・権限管理・暗号化・操作監査は今回確認した集計処理にはない。
- 入力・出力・履歴の保存期限管理、自動定期バックアップ、複数利用者の同時実行制御は集計処理に実装されていない。性能・可用性の保証値はコードから確定できない。

### 7.1 別起動のメール・送信ブック機能

- `送信.bat` はPythonで `tool/send_mail.py` を起動する。Outlook COMとpywin32を使用する。
- `tool/送信設定.csv` から宛先・CC・件名・本文を読み、件名・本文の `{年}`・`{月}`・`{日}` を支給日で置換する。宛先が未設定または「@」を含まなければ中止する。
- 対象日は第1引数で指定でき、省略時はファイル名順で最後の共有用Excelを添付する。通常実行ではOutlookのSendを呼ぶ。
- 確認事項テキストから警告を抽出できた場合は送信を中止する。確認事項ファイルが存在しない場合は警告なしとして継続する。
- コードには確認モードもある。対象日の第1引数とは別に `--dry-run` 等を渡すと、Outlookメールを作成後に削除し、送信しない。
- `tool/send_book.py` はExcel COMで送信ボタン付きブックを作成・更新する関数を備える。マクロ本体は手動設置を前提とする。現在の `payroll.py` は更新関数を呼び出さず、通常の集計で送信ブックは更新されない。既存xlsm内のマクロの実体は未検証。
