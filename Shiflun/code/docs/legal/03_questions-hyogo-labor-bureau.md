# 3. 兵庫労働局への質問事項

[← 目次に戻る](README.md)

## 相談の目的

飲食業界向けマッチングサービス「Shiflun」の本格営業・契約開始前に、職業安定法・労働基準法その他関係法令上、現在の事業設計に問題がないか、また必要な許可・届出があるかを事前に確認したい。

## サービス概要（要約）

詳細は [01_service-overview.md](01_service-overview.md) を参照。要点のみ以下に記載する。

- 飲食業界に特化し、店舗の日常のシフト管理をフックにしたワーカー・店舗マッチングサービス（現状はヒアリング用デモMVP、Web）。
- ワーカーが勤務可能日時を登録 → 勤務先店舗の店長が「自店採用」か「他店舗へ開放」かを判定 → 開放分について他店舗が条件検索し、**個別に時給等の条件を提示してスカウトを送信** → ワーカーが承諾した時点で、勤務先店舗とワーカーの間に契約が成立する、という整理を現行の利用規約案は取っている。
- Shiflun は契約の当事者にならず、契約内容についても責任を負わないという立て付け（利用規約第5条4項・第10条）。
- 収益は、店舗からの「利用料または成果報酬型手数料」（利用規約第7条2項）。要件定義書上の構想は「実際に勤務が行われた実績報酬から一定割合を店舗へ請求」する完全成果報酬型。ワーカーからは徴収しない。
- お金の流れの案は [02_money-flow.md](02_money-flow.md) を参照（現時点では未確定、無仲介案・決済プラットフォーム介在案を検討中）。

## 質問事項

### Q1. 有料職業紹介事業に該当するか

> **【回答済み・要記録】** 弁護士・自治体（市役所）への相談で、スカウト機能自体（個別条件提示＋成果報酬型手数料）は有料職業紹介事業に該当しないことを確認できた（相談日：要記入。詳細は [05_open-issues.md](05_open-issues.md) #2・相談履歴を参照）。一方、別途指摘された店舗所属の店長承認フローについては#14のとおり自己申告制＋通報機能に変更済みで、この対応自体が十分かは未確認。兵庫労働局にも同じ回答が得られるか、また判断の前提条件（今回の自己申告制への変更を織り込んだ前提かどうか）を確認したい。

**背景**: 本サービスの「スカウト」機能は、店舗が検索条件（勤務可能日時・スキルタグ等）でワーカーを絞り込み、個別に時給・勤務日時等の条件を提示して直接勧誘し、ワーカーが承諾すれば店舗・ワーカー間に契約（雇用等）が成立する、という設計です。また店舗からは成果報酬型の手数料を徴収する構想です。

**質問**:
- このスカウト機能（条件を指定した個別のワーカーへの勧誘＋成果報酬型手数料）は、職業安定法上の「職業紹介」（求人・求職の申込みを受け、求人者と求職者との間における雇用関係の成立をあっせんすること）に該当するか。
- 該当する場合、有料職業紹介事業（職業安定法30条）の許可が必要か。

### Q2. 募集情報等提供事業に該当するか

**背景**: 2022年の職業安定法改正により「募集情報等提供事業」（原則届出不要、収集した求人情報等を加工提供する場合は「特定募集情報等提供事業」として届出制）という枠組みが整理されています。

**質問**:
- スカウト機能を含む本サービス全体が「募集情報等提供事業」に該当するか。該当する場合、「特定募集情報等提供事業」の届出が必要な要件を満たすか。
- Q1（職業紹介）とQ2（募集情報等提供）の切り分けの考え方、および本サービスの現在の設計（個別スカウト＋成果報酬）がどちらに近いか。

### Q3. 必要な許可・届出

**背景**: Q1・Q2の該当性次第で必要な手続きが変わる。

**質問**:
- Q1・Q2の判断結果に応じて、具体的にどの許可・届出が必要か（有料職業紹介事業許可、募集情報等提供事業届出、特定募集情報等提供事業届出 等）。
- それぞれの取得に必要な要件（財産的基礎、事業所要件、責任者の要件等）と、取得にかかる期間の目安。
- 本格営業開始のスケジュールとの関係で、何を先に準備すべきか。

### Q4. 店舗とワーカーの労働契約成立方法

**背景**: 現行の利用規約案（第5条3項）は「ワーカーがスカウトを承諾し、店舗とワーカー双方が合意した時点で契約成立」としていますが、雇用契約か業務委託契約かは規約上明記していません（[01](01_service-overview.md) 1.5節参照）。

**質問**:
- アプリ上のワンタップ承諾によって、法的に有効な労働契約（または業務委託契約）が成立したと言えるための最低限の要件は何か。
- Shiflun のように契約当事者にならない仲介事業者が、契約成立の記録（ログ）を保持しておくことに何か法的な意味・義務があるか。

### Q5. アプリ上で労働条件提示→承諾する方式

**背景**: 現在のスカウト画面（`app/companies/workers/[id]/scout`）で提示される情報は、店舗名・希望勤務日・時間帯・提示時給・自由記述メッセージのみです。労働基準法15条が定める労働条件明示事項（賃金、労働時間、休憩、休日、解雇の事由等）を網羅的にカバーする設計にはなっていません。

**質問**:
- スポットワーカー向けのマッチングアプリにおいて、アプリ上での条件提示＋ワンタップ承諾という方式で労働基準法15条（労働条件の明示）を満たすには、最低限どの項目を画面に表示し、記録として残す必要があるか。
- 書面交付に代わる電子的方法（本人が容易に出力できる形式での明示等）として、アプリでの表示・記録がどこまで有効か。
- この義務は店舗（使用者）が負うものと理解しているが、Shiflun が画面設計としてどこまで支援・担保すべきか。

### Q6. 給与支払方法

**背景**: [02_money-flow.md](02_money-flow.md) のとおり、Shiflun は給与を立て替えない前提で、店舗が直接ワーカーへ支払う案（案A）と、決済プラットフォームを介する案（案B）を検討中です。

**質問**:
- 店舗がワーカーへ直接支払う場合、労働基準法24条（賃金の直接払い・全額払い・毎月一回以上・一定期日払いの原則）との関係で、単発・スポット勤務であっても留意すべき点は何か。
- 決済代行会社・決済プラットフォームを介して店舗からワーカーへ送金する構成（案B）は、24条の「直接払いの原則」との関係でどう整理されるか。
- 雇用契約ではなく業務委託契約と整理した場合、上記の適用関係はどう変わるか。

### Q7. 勤怠

**背景**: 現行の実装では、ワーカーが自らボタンを押すことで勤務ステータスを「出勤済み」に更新するのみで、GPSや店舗設置QRコード等による客観的な打刻は未実装です（将来構想として検討中）。また、スカウトが成立した他店舗での勤務について、勤怠打刻機能自体が現状連携されていません（[01](01_service-overview.md) 1.3節参照）。

**質問**:
- スポットワーカーの労働時間管理として、労働基準法上、店舗（使用者）に求められる客観的な記録方法・保存義務の水準はどの程度か。
- 自己申告のみの打刻は労働時間管理の方法として不十分か。GPS・QRコード等による客観的記録が必須と言えるか。
- Shiflun（仲介事業者）がこの記録の一部（勤務日時の合意内容等）を保持することは、店舗の労働時間管理義務を代替・補完しうるか、それとも無関係か。

### Q8. 労災

**背景**: 現行の利用規約案第16条は、勤務中の事故等について「雇用関係にある店舗が使用者として労働基準法その他関係法令に基づく対応を行う」「当社は使用者・被用者関係に該当しない」としています。

**質問**:
- この整理（店舗のみが労災保険の適用関係を検討すべき使用者であり、Shiflunは無関係）で問題ないか。
- スポットワーカーが複数店舗を短時間・単発で掛け持ちする働き方において、労災保険の適用関係（どの店舗の労災保険が適用されるか、複数事業労働者に関する給付調整等）で、店舗・Shiflunそれぞれが留意すべき点は何か。
- 業務委託契約と整理した場合、労災保険特別加入制度との関係はどうなるか。

### Q9. 源泉徴収

**背景**: 契約が雇用（給与所得）か業務委託（報酬・料金）かによって、源泉徴収義務者・方法が異なりうるが、現行の利用規約案では明記されていません。

**質問**:
- 本サービスを通じた契約が雇用か業務委託かの整理によって、源泉徴収の要否・方法・義務者はどう変わるか。
- 単発・スポット勤務の場合に特有の留意点があるか。
- ※源泉徴収の詳細な取扱いは税務署・税理士の所管である可能性が高いことは認識しており、労働局として関連する範囲（労働契約性の判断等）を中心に伺いたい。
