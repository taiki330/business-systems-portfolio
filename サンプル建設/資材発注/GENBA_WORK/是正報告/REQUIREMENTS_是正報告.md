# 是正報告システム — 要件メモ（ヒアリング録音ベース）

## 目的

- 巡回側が入力した指摘・写真がそのままデータ化され、**スプレッドシート／帳票**に反映されること。
- **建築会社（元請）・施工会社**が迷わないよう、**報告区分・請負・施工**の役割を画面上で区別できること。

## 運用フロー（概要）

1. 巡回（営業）が現場を確認し、指摘・是正依頼を登録する。
2. **提出期日**は **営業日ベース**（`AppConfig.businessDaysToSubmit`、既定 3）で自動計算。**巡回日その日は常にカウントしない**、翌日以降のみ数える。**土曜は営業日に含める**（祝日カレンダー上が休みの土曜のみ除く）。**日曜および月〜金の祝日**は含めない（Google 公式「日本の祝日」カレンダー）。初回はデプロイアカウントでカレンダー再認証が必要な場合あり。
3. 現場側は共有 URL から **是正後写真**をアップロードする。
4. 巡回側が内容を確認し、**承認**または**差し戻し**を行う。

## 画面・データ（実装済みの方向性）

| 項目 | 内容 |
|------|------|
| 報告区分 | プルダウン（足場点検・稼働現場巡回・安全衛生協議会・立会い・その他）。`AppConfig.reportCategoryOptions` で変更可能。 |
| 現場名 | マスタ連携の候補表示（入力補助）。 |
| 請負業者名 | **必須**。業者マスタ（1行目ヘッダーの下）「請負業者名」列の値からのみプルダウン選択。 |
| 施工会社名 | **必須**。請負選択後、業者マスタの B 列に加え **請負業者名と同名の選択肢を先頭に追加**（ラベルは請負名のみ）。手入力なし。 |
| 承認画面の一時保存 | 案件詳細で「差し戻し理由」等を **localStorage** に保存（端末内）。ボタン「一時保存（この端末・差し戻し理由）」。承認／差し戻し成功後は当該明細の下書きのみ削除。 |
| 提出期日（新規入力欄） | 巡回日**未入力**は「巡回日を入力すると自動計算します」。入力後は **`YYYY/MM/DD (N営業日後)`**（`previewSubmitDeadline` と一致）。計算失敗時は `0000/00/00 (N営業日後)`。 |
| 報告者・巡回者・点検者 | 氏名テキスト。 |
| 指摘明細 | 種別（例：職是正／良好）、指摘事項、是正内容、是正前写真。 |
| 請負業者別ビューア | 請負業者ごとに配布するURL `?mode=rect-viewer&prime=請負業者名` から、その請負業者に紐づく是正案件の一覧を閲覧専用で表示。カードから既存の共有URL（`Upload.html?caseId=…`）を新規タブで開き、是正後アップロード画面へ遷移できる。案件シートへの書き込みは行わない（読み取り専用）。 |

## スプレッドシート移行（重要）

**案件シート**に **「請負業者名」** 列を **最右列（従来の「更新日時」の右隣）** として追加してください。

1. 既存の 1 行目ヘッダーの右端に列を 1 列追加する。  
2. 新しい列の 1 行目に `請負業者名` と入力する。  

列を追加しない状態で保存すると、最右列にデータだけ入りヘッダーとずれる恐れがあるため、**デプロイ前に実施**を推奨します。

## 実装済み（録音要約との対応）

- **期限アラート（一覧）**: 提出期日を過ぎ、かつ未提出明細が残る案件に「期限超過」バッジ。一覧タブ「期限超過」で絞り込み。詳細・現場アップロード画面に警告表示。
- **写真の枠内表示**: 縦横どちらの写真も、枠内に全体が収まるよう `object-fit: contain`（トリミングしすぎない）。

## 今後の拡張候補

- **メール／プッシュ通知**による期限通知（一覧は対応済み）。
- 写真の **向きの自動回転**やサーバー側の一括リサイズ。
- 帳票 PDF のレイアウト（1 ページあたりの写真枚数など）。
